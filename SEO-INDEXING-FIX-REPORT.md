# SEO Indexing Diagnosis — propknown.com

**Date:** 2026-07-18
**Finding: no technical blocking issue exists in the current or historical codebase.** All six hypotheses in the diagnostic checklist were tested against the live production site and the full git history, and every one came back clean. This report documents the evidence for each, then explains the far more likely (and mundane) real cause: the site is ~25 days old and has probably never been submitted to Google.

## Diagnosis: checked in order, nothing found

```

No `X-Robots-Tag` header anywhere. Checked on: homepage, `/buy`, `/contact`, `/pricing`, `/robots.txt`, `/sitemap.xml` — and re-checked every one again spoofed as Googlebot's exact user-agent string (`Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)`) in case Vercel's bot/firewall handling treated it differently. Identical `200 OK`, identical headers, no `X-Robots-Tag` in any case.

There is also no `middleware.ts` in the project, no `vercel.json`, and `next.config.mjs` contains only an `images.remotePatterns` block — none of the three places that could inject a response header exist or do so.

### 3. `noindex` in root metadata

  index: true,

Confirmed rendered into the actual served HTML:
```
$ curl -s https://www.propknown.com/ | grep -io '<meta[^>]*robots[^>]*>'

A repo-wide grep for `noindex` found exactly one match: `app/(public)/account/layout.tsx`, which deliberately sets `robots: { index: false, follow: true }` on the logged-in `/account` dashboard only. That's correct, intentional (added in a prior SEO-audit session alongside `/admin` and `/crm` noindex, since none of those three have unique public content worth indexing) — and scoped to those three routes, not site-wide. `git log --all -S "index: false" -- app/layout.tsx` returns nothing: the root layout has never set `index: false`.

## Root cause: there isn't one — the site just hasn't been crawled yet

Every mechanism that could block Googlebot from crawling and indexing propknown.com is, and — per git history — always has been, configured correctly. That means the "zero pages indexed" result is not a bug to fix; it's the expected state of a domain that is:

- **~25 days old** (Vercel project created 2026-06-23; SSL cert issued the same day)
- **Very likely never manually submitted** to Google Search Console (no sitemap ping, no "Request Indexing")
- **Has few or no inbound backlinks yet**, so Googlebot has no organic path to discover it — new sites with no external links pointing to them can sit un-crawled for weeks purely because nothing told Google they exist

This is normal, not a defect. `site:` returning nothing for a 3–4-week-old domain with no Search Console submission and no backlinks is the median outcome, not an anomaly.

## Next steps — manual actions only you can do

None of the following can be done via code or CLI from here; they require your Google account access.

1. **Verify the domain in Google Search Console** (search.google.com/search-console): add `propknown.com` as a **Domain property** (covers `www` and non-`www`, and any subdomain, in one go) rather than a URL-prefix property. Verification is via a DNS TXT record — add it at whatever registrar/DNS host manages `propknown.com`.
2. **Submit the sitemap**: once verified, in Search Console → Sitemaps, submit `https://www.propknown.com/sitemap.xml`. This gives Google an explicit, complete list of all 33 URLs in one shot instead of waiting for organic discovery.
3. **Request Indexing on the homepage specifically**: Search Console → URL Inspection → enter `https://www.propknown.com/` → "Request Indexing." This is the single fastest lever — it queues an on-demand crawl instead of waiting for Google's normal discovery crawl cycle.
4. **Optional but genuinely helpful**: get at least one real backlink pointing at the site (a business directory listing, a social profile bio link, a partner site) — new domains with zero backlinks are crawled far more slowly than ones with even one or two inbound links, since backlinks are one of Google's main discovery signals for new sites.

### Realistic timeline
- **Homepage**: typically **3–14 days** after "Request Indexing," assuming no re-review issues.
- **Rest of the 33 sitemap URLs**: **2–6 weeks** for the bulk of them, longer tail for lower-priority pages (privacy/terms/disclaimer) which Google crawls less eagerly regardless of technical health.
- This is normal pace for a new domain with correct technical SEO (which this site has) — the bottleneck from here on is purely discovery/authority, not anything fixable in code.
